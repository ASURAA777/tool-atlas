How to interpret the verdicts

Build now: a documented free, trial or local path exists for a scoped prototype. Usage charges, permissions or distribution reviews may still apply.

With conditions: API or MCP is documented, but paid access, admin permissions, app review, partner approval or unconfirmed eligibility materially affects implementation.

Investigate: entity identity or sufficient integration evidence remains unresolved. No source absence is treated as proof of no API.

Blocked: a documented restriction prevents the proposed toolkit scope. This is different from paid or partner-gated access.

What was built

A research pipeline with evidence.

The executed pass used Codex research agents to search official sources and produce structured records. A targeted sample check challenges those answers. Python validates the records and builds this page from the same JSON.

The included standalone runner can repeat discovery and verification through a model with web search. It saves first-pass answers, raw responses, checks and revised answers separately. Its paid model execution has not been run here.

Implementation choices and limits

This submission uses a small standard-library Python pipeline and a buildless HTML report. Composio SDK/MCP was not used in the executed run. The design favors inspectable evidence over adding an integration layer unrelated to public-doc research. A future production version could use Composio for authenticated app probes after credentials are approved.

“Agent-checked” is not “human-verified.” Link reachability is not claim accuracy. No authenticated endpoint smoke tests, account creation or paid-plan purchases were performed. The frozen first pass and independent verification ledger are included in source.

The fresh runner makes two model calls per app, uses bounded retries, resumes completed records and keeps results separate from the published dataset. It incurs model/search charges and requires a compatible Responses API model. Review its output before promoting it.

Sampling, denominators and source checks

The human-review worksheet uses seed 20261123 and selects two apps from each of the ten categories. Check five fields per app: auth, access, API surface, MCP and verdict. A complete manual audit would contain 100 field judgments. An unresolved claim stays in the denominator and is not counted as correct.

Agent agreement can share the original model’s blind spots; it is not an independent estimate of overall accuracy. The next useful validation is human source review and, where credentials are available, a read-only endpoint test.

From research to roadmap

Three queues. Different next steps.

Prototype a narrow action.

Start with a documented credential path and a useful read operation. Test auth, pagination and rate limits before widening the toolkit.

Resolve the gate first.

Separate sandbox work from production onboarding. Assign an owner to plan eligibility, admin consent or public-app review before committing an integration date.

Ask a precise question.

For unclear vendors, confirm identity, API availability and credential eligibility. Preserve unknowns so the roadmap reflects evidence rather than guesses.
